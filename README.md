# tt-task-skill

สกิลสำหรับผู้ช่วย AI (agent เช่น Claude Code) ให้ทำงานกับระบบ **TimeThunder Audit Manager** ผ่าน API แทนพนักงานได้ เช่น

- ดูรายการงาน ลูกค้า ผู้สอบ และยอดเงินในระบบ
- กรอก "ข้อมูลปิดงาน" 4 ช่อง (วันที่หน้ารายงาน, รูปแบบหน้ารายงาน, รายได้จริง, ค่าสอบจากงบการเงิน) โดยอ่านจากไฟล์ในโฟลเดอร์ WP แล้วให้พนักงานตรวจอีกที

สกิลนี้**อนุมัติส่งมอบงานเองไม่ได้** พนักงานต้องเป็นคนตรวจและกดอนุมัติเสมอ

คู่มือนี้พาทำตั้งแต่ดาวน์โหลดจนลองใช้ครั้งแรกได้ ทำตามทีละขั้นได้เลย ไม่ต้องเขียนโปรแกรมเป็น

## ขั้นที่ 1: ติดตั้งโปรแกรมที่ต้องใช้

| โปรแกรม | รุ่น | ใช้ทำอะไร |
|---|---|---|
| [Node.js](https://nodejs.org) | **22 หรือ 24 (รุ่น LTS)** อย่างต่ำ 20.6 | ใช้รันตัวติดตั้งและตัวเรียก API |
| [Git](https://git-scm.com/downloads) | รุ่นไหนก็ได้ | ใช้ดาวน์โหลดสกิลนี้ |
| Dropbox (โปรแกรมบนเครื่อง) | รุ่นปัจจุบัน | ให้ไฟล์ WP อยู่บนเครื่อง เพราะสกิลอ่านไฟล์จาก API ไม่ได้ (ดูหัวข้อ "ข้อจำกัด") |
| ผู้ช่วย AI ที่อ่านสกิลได้ | เช่น Claude Code | ตัวที่จะใช้สกิลนี้ |

เปิดโปรแกรม Terminal (Mac) หรือ PowerShell (Windows) แล้วพิมพ์ทีละบรรทัดเพื่อเช็กว่าติดตั้งแล้ว

```sh
node --version
git --version
```

ถ้า `node --version` ขึ้นเลขต่ำกว่า `v20.6` ให้ติดตั้ง Node.js รุ่น LTS ใหม่จาก nodejs.org ก่อน

> ทุกคำสั่งในคู่มือนี้ใช้ได้ทั้ง Terminal บน Mac และ PowerShell บน Windows

## ขั้นที่ 2: ดาวน์โหลดสกิล

```sh
git clone https://github.com/peerasak-u/tt-task-skill.git
cd tt-task-skill
```

หลังจากนี้ให้รันทุกคำสั่งในโฟลเดอร์ `tt-task-skill` นี้

ลองเช็กว่าตัวเรียก API รันได้

```sh
node skills/tt-task-skill/scripts/tt.mjs --help
```

ถ้าขึ้นข้อความที่เริ่มด้วย `usage:` และรายการคำสั่ง (`get`, `command`, `closing-queue`, `closing-plan`, `fill-closing`) แปลว่าใช้ได้ คำสั่งนี้แค่แสดงวิธีใช้ ไม่ได้ติดต่อระบบ (โปรแกรมจะจบด้วยสถานะ "ผิดพลาด" เป็นเรื่องปกติของคำสั่งนี้ ไม่ต้องสนใจ)

## ขั้นที่ 3: ขอ API token

token คือ "กุญแจ" ที่ให้สกิลเข้าระบบ TimeThunder แทนเรา **ต้องให้พนักงานที่ล็อกอินเว็บ TimeThunder ได้เป็นคนออกให้** token ออก token เองไม่ได้

**ถ้าคุณมีบัญชีพนักงานของ TimeThunder ทำเองได้ดังนี้**

1. เข้าเว็บ TimeThunder ของสำนักงานแล้วล็อกอิน
2. ไปที่เมนู **ตั้งค่า** แล้วเลือกแท็บ **Developer** (หรือเปิด `https://<ที่อยู่ TimeThunder>/settings?tab=developer`)
3. ในหัวข้อ **API token** พิมพ์ป้ายชื่อในช่อง "ชื่อเครื่องมือ" เช่น `mai-agent` แล้วกดปุ่ม **ออก token**
4. หน้าต่างจะแสดง token ที่ขึ้นต้นด้วย `tt_` **ระบบแสดงแค่ครั้งเดียว** ให้กดคัดลอกแล้วไปทำขั้นที่ 4 ต่อทันที จากนั้นค่อยกด "คัดลอกแล้ว ปิด"

**ถ้าไม่มีบัญชีพนักงาน** ให้ขอผู้ดูแลระบบ TimeThunder ของสำนักงานออก token ให้ และให้ส่งมาทางที่ปลอดภัย (ไม่ส่งในกลุ่มแชต)

ข้อควรระวังเรื่อง token

- token มีสิทธิ์อ่านข้อมูลทั้งหมด และทำคำสั่งเรื่องงานกับเงินได้ ให้ระวังเหมือนรหัสผ่าน
- ห้ามแปะ token ในแชต อีเมล หรือคุยกับผู้ช่วย AI
- ถ้าคิดว่า token หลุด ให้พนักงานกด **เพิกถอน** ในแท็บ Developer แล้วออกอันใหม่

## ขั้นที่ 4: ใส่ token และติดตั้งสกิลเข้าผู้ช่วย AI

ระบบอ่านค่า 3 ตัวนี้

| ชื่อ | ความหมาย | ตัวอย่าง (ค่าปลอม) |
|---|---|---|
| `TT_API_URL` | ที่อยู่เว็บ TimeThunder ไม่ต้องมี `/api` ต่อท้าย | `https://your-timethunder.example` |
| `TT_API_TOKEN` | token จากขั้นที่ 3 | `tt_xxxxxxxxxxxxxxxx` |
| `TT_DROPBOX_DIR` | โฟลเดอร์ Dropbox บนเครื่องนี้ | `/Users/yourname/Dropbox` หรือ `C:\Users\yourname\Dropbox` |

### วิธีที่ 1 (แนะนำ): ให้ตัวติดตั้งถามทีละข้อ

```sh
node skills/tt-task-skill/install.js
```

ตัวติดตั้งจะถาม 4 ข้อ

1. **จะติดตั้งที่ไหน** ตอบ `1` (ทุกโปรเจกต์ในเครื่องนี้) ถ้าไม่แน่ใจให้กด Enter ได้เลย
2. **TimeThunder address** ใส่ที่อยู่เว็บ TimeThunder เช่น `https://your-timethunder.example`
3. **API token** วาง token จากขั้นที่ 3 ตอนพิมพ์จะมองไม่เห็นตัวอักษร เป็นเรื่องปกติ แล้วกด Enter ตัวติดตั้งจะลองเชื่อมต่อให้ก่อนบันทึก
4. **Dropbox folder** ใส่ที่อยู่โฟลเดอร์ Dropbox บนเครื่อง (ถ้ามีโฟลเดอร์ `Dropbox` ในโฟลเดอร์บ้าน ระบบจะเดาให้ กด Enter ได้) ถ้าเครื่องนี้ไม่มี Dropbox ให้ตอบ `-`

ถ้าสำเร็จจะขึ้น `The token works.` และ `Skill installed in:` ตามด้วยที่อยู่ที่ติดตั้ง

ตัวติดตั้งทำ 2 อย่าง

- คัดลอกสกิลไปไว้ที่ `~/.claude/skills/tt-task-skill` และ `~/.agents/skills/tt-task-skill` ให้ผู้ช่วย AI เห็น
- เก็บที่อยู่ token และโฟลเดอร์ Dropbox ไว้ในไฟล์ที่ผู้ใช้คนนี้อ่านได้คนเดียว
  - Mac/Linux: `~/.config/tt-task-skill/config.json`
  - Windows: `%APPDATA%\tt-task-skill\config.json`

ต้องการเปลี่ยน token หรืออัปเดตสกิล ให้รันคำสั่งเดิมซ้ำ

### วิธีที่ 2: ใช้ไฟล์ `.env` (สำหรับคนที่ไม่อยากตอบคำถาม)

```sh
cp .env.example .env
```

(บน Windows PowerShell ใช้ `Copy-Item .env.example .env`)

เปิดไฟล์ `.env` ด้วยโปรแกรมแก้ข้อความ แล้วแทนค่าตัวอย่างด้วยค่าจริง หน้าตาเป็นแบบนี้ (ค่าข้างล่างเป็นค่าปลอม)

```sh
TT_API_URL=https://your-timethunder.example
TT_API_TOKEN=tt_xxxxxxxxxxxxxxxx
TT_DROPBOX_DIR=/Users/yourname/Dropbox
```

จากนั้นติดตั้งโดยไม่ต้องตอบคำถาม (ใส่ที่อยู่และโฟลเดอร์ Dropbox เดียวกับใน `.env`)

```sh
node --env-file=.env skills/tt-task-skill/install.js --scope user --url https://your-timethunder.example --dropbox-dir /Users/yourname/Dropbox
```

ถ้าเครื่องนี้ไม่มี Dropbox ให้ใช้ `--no-dropbox` แทน `--dropbox-dir ...`

ไฟล์ `.env` ถูกกันไม่ให้ขึ้น git ไว้แล้วใน `.gitignore` แต่ห้ามส่งไฟล์นี้ให้ใคร หลังติดตั้งเสร็จ ค่าทั้งหมดถูกเก็บในไฟล์ config ของขั้นนี้แล้ว จะลบ `.env` ทิ้งก็ได้

> สกิลไม่ได้อ่านไฟล์ `.env` เอง ผู้ช่วย AI ใช้ค่าที่ตัวติดตั้งเก็บไว้ ถ้าอยากใช้ `.env` ตรงๆ ต้องใส่ `node --env-file=.env` นำหน้าทุกคำสั่ง

## ขั้นที่ 5: เช็กว่าใช้ได้

คำสั่งนี้แค่**อ่าน**ปีดำเนินงานปัจจุบัน ไม่ได้แก้อะไรในระบบ

```sh
node skills/tt-task-skill/scripts/tt.mjs get /settings/operate-year
```

**ถ้าสำเร็จ** จะขึ้นประมาณนี้ (ตัวเลขของจริงอาจต่าง)

```json
{
  "currentOperateYear": 2569,
  "jobNumberFloor": 1
}
```

**ถ้าไม่สำเร็จ** จะขึ้นข้อความแบบใดแบบหนึ่ง

| ข้อความ | แปลว่า | แก้ยังไง |
|---|---|---|
| `GET /settings/operate-year answered 401: กรุณาเข้าสู่ระบบ` | token ผิด หมดสิทธิ์ หรือถูกเพิกถอน | ขอ token ใหม่ (ขั้นที่ 3) แล้วรันตัวติดตั้งซ้ำ |
| `no apiUrl in .../config.json and TT_API_URL is not set; ...` | ยังไม่ได้ติดตั้ง | ทำขั้นที่ 4 |
| `no apiToken in .../config.json and TT_API_TOKEN is not set; ...` | มีที่อยู่แต่ยังไม่มี token | ทำขั้นที่ 4 ใหม่ |
| ข้อความยาวหลายบรรทัดที่มีคำว่า `TypeError: fetch failed` | ต่อเว็บ TimeThunder ไม่ได้ | เช็กอินเทอร์เน็ต และที่อยู่เว็บว่าพิมพ์ถูก แล้วรันตัวติดตั้งซ้ำ |

ตอนติดตั้ง ถ้า token ผิดจะขึ้น `TimeThunder refused the token: it is wrong or revoked` ถ้าต่อเว็บไม่ได้จะขึ้น `could not reach ...` และถ้าโฟลเดอร์ Dropbox ที่ใส่ไม่มีอยู่จริงจะขึ้น `there is no folder at ...` ทุกกรณีตัวติดตั้งจะไม่บันทึกอะไร

## ขั้นที่ 6: ลองใช้ครั้งแรก (อ่านอย่างเดียว ไม่แก้ข้อมูล)

ดูรายการงานที่เริ่มแล้วแต่ข้อมูลปิดงานยังไม่ครบ

```sh
node skills/tt-task-skill/scripts/tt.mjs closing-queue
```

ผลที่ได้เป็นรายการงาน แต่ละงานมี `jobId` (เลขภายในระบบ) และ `jobNumber` (เลขงานที่เราเห็นกัน) จากนั้นเลือก `jobId` มา 1 งานแล้วดูว่าขาดอะไร และโฟลเดอร์ WP อยู่ที่ไหน

```sh
node skills/tt-task-skill/scripts/tt.mjs closing-plan <jobId>
```

ใส่ตัวเลข `jobId` แทน `<jobId>` เช่น `closing-plan 123` แล้วดูช่อง `localWpFolder`

- เป็น `null` แปลว่ายังไม่ได้ตั้งโฟลเดอร์ Dropbox ตอนติดตั้ง
- มี `path` แต่ `files` เป็น `null` แปลว่าโฟลเดอร์ WP ของงานนี้ยังไม่ sync ลงเครื่อง ให้เปิด Dropbox แล้วรอ sync หรือเลือกให้โฟลเดอร์นั้นเก็บไว้บนเครื่อง
- มีรายชื่อไฟล์ใน `files` แปลว่าพร้อมให้ผู้ช่วย AI อ่าน

ทั้งสองคำสั่งอ่านอย่างเดียว ลองได้ไม่ต้องกังวล

### ใช้กับผู้ช่วย AI

เปิดผู้ช่วย AI ใหม่ (ปิดของเดิมก่อน) แล้วสั่งเป็นภาษาธรรมดาได้เลย เช่น

> ช่วยดูงานที่ข้อมูลปิดงานยังไม่ครบใน TimeThunder หน่อย

> กรอกข้อมูลปิดงานของงานเลขที่ ... จากโฟลเดอร์ WP ให้หน่อย ลอง dry-run ก่อนนะ

ก่อนเขียนข้อมูลจริง สกิลจะลองแบบ `--dry-run` (จำลอง ไม่บันทึก) ก่อนเสมอ และจะเขียนเฉพาะช่องที่ยังว่าง ทุกครั้งที่เขียนจะทิ้งโน้ตบอกที่มาของแต่ละค่าไว้ในงาน ให้พนักงานตรวจ

## ข้อจำกัด (สิ่งที่ยังทำไม่ได้)

- **อ่านเนื้อหาไฟล์ผ่าน API ไม่ได้** API บอกได้แค่ชื่อไฟล์ ไม่ส่งตัวไฟล์ ดังนั้นต้องมีโฟลเดอร์ Dropbox ที่ sync ไฟล์ WP ลงเครื่องนี้แล้ว ถ้าไม่มี สกิลจะบอกว่าโฟลเดอร์ WP ไม่อยู่บนเครื่องแล้วหยุด (ไม่เดาค่าจากชื่อไฟล์)
- **อนุมัติส่งมอบงาน และยืนยันเริ่มงานไม่ได้** ต้องเป็นพนักงานบนเว็บ
- **ออก/เพิกถอน token จัดการพนักงาน และเชื่อม Dropbox ไม่ได้** ต้องเป็นพนักงานบนเว็บ
- **อัปโหลดไฟล์ (สลิป ไฟล์รับงาน) ไม่ได้** ตัวเรียก API ยังไม่รองรับการส่งไฟล์

## ลบสกิลออก

1. ลบโฟลเดอร์ `~/.claude/skills/tt-task-skill` และ `~/.agents/skills/tt-task-skill`
2. ลบไฟล์ `~/.config/tt-task-skill/config.json` (Windows: `%APPDATA%\tt-task-skill\config.json`)
3. ให้พนักงานกด **เพิกถอน** token นั้นในแท็บ Developer
